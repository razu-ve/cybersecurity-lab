# Network Basics

## Objective

Understand the basic network configuration of the CyberLab host,
including network interfaces, IP addressing, routing, DNS, and
basic connectivity testing.

---

## 1. Network Interfaces

### 1.1 View IP Addresses

Command:

    ip addr

Purpose:

Displays network interfaces, MAC addresses, IPv4/IPv6 addresses,
interface state, and other addressing information.

Observed interfaces:

- `lo` — Loopback interface
- `wlp1s0` — Wireless interface
- `vmnet1` — VMware host-only network
- `vmnet8` — VMware NAT network

---

### 1.2 View Network Links

Command:

    ip link

Purpose:

Displays network interfaces and link-layer information,
including interface state and MAC addresses.

The active wireless interface is:

- Interface: `wlp1s0`
- State: `UP`

---

## 2. Network Interfaces

### 2.1 Loopback

- Interface: `lo`
- IPv4: `127.0.0.1/8`
- Purpose: Local communication within the host.

The loopback interface allows applications on the same system
to communicate with each other without using the physical network.

---

### 2.2 Wi-Fi

- Interface: `wlp1s0`
- IPv4: `10.x.x.x/24`
- Status: `UP`
- Address assigned dynamically via DHCP.

The Wi-Fi interface provides the host's primary network
and Internet connectivity.

---

### 2.3 VMware Networks

#### VMnet1

- Interface: `vmnet1`
- IPv4: `172.16.x.x/24`
- Purpose: VMware host-only networking.

VMnet1 provides a private virtual network between the host
and virtual machines configured to use the host-only network.

#### VMnet8

- Interface: `vmnet8`
- IPv4: `172.16.x.x/24`
- Purpose: VMware NAT networking.

VMnet8 allows virtual machines to access external networks
through NAT using the host's network connection.

---

## 3. Routing

### 3.1 View Routing Table

Command:

    ip route

Purpose:

Displays the system's routing table and shows where network
traffic is sent.

Observed routing structure:

- Default route through the Wi-Fi interface.
- Directly connected Wi-Fi network.
- VMware VMnet1 network.
- VMware VMnet8 network.

The default route is associated with:

    wlp1s0

The gateway is in the private `10.x.x.x` address range.

---

## 4. DNS

### 4.1 View DNS Configuration

Command:

    cat /etc/resolv.conf

Purpose:

Displays the DNS resolver configuration used by the system.

The file is generated by NetworkManager.

A local/private DNS resolver is configured for hostname
resolution.

---

## 5. Connectivity Tests

### 5.1 IPv4 Connectivity

Command:

    ping -c 4 8.8.8.8

Purpose:

Tests IPv4 connectivity to Google's public DNS server.

Result:

- 4 packets transmitted
- 4 packets received
- 0% packet loss
- IPv4 connectivity confirmed

---

### 5.2 DNS and Hostname Connectivity

Command:

    ping -c 4 google.com

Purpose:

Tests both hostname resolution and network connectivity.

The hostname `google.com` was successfully resolved to an IPv6
address and ICMP echo requests received replies.

Result:

- 4 packets transmitted
- 4 packets received
- 0% packet loss
- DNS resolution successful
- Network connectivity confirmed

---

## 6. Commands Used

The following commands were used during this experiment:

    ip addr
    ip link
    ip route
    cat /etc/resolv.conf
    ping -c 4 8.8.8.8
    ping -c 4 google.com

---

## 7. Key Observations

- The primary network interface is `wlp1s0`.
- The Wi-Fi interface receives its IPv4 address dynamically.
- The host has both IPv4 and IPv6 connectivity.
- The default route uses the Wi-Fi interface.
- DNS is managed through NetworkManager.
- VMware provides additional virtual networks through `vmnet1`
  and `vmnet8`.
- IPv4 Internet connectivity was confirmed using `8.8.8.8`.
- DNS resolution and hostname connectivity were confirmed using
  `google.com`.
